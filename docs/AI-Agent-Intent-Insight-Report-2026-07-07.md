## 新增趋势洞察

### 1. 本体从静态先验到动态推导
本体建模经历了范式转变：传统方法依赖专家预定义本体，新方法让 LLM 根据任务自动构建。[[ORACLE]] 为每个问题动态构建特定本体，[[TeQoDO]] 用 SQL 能力从零构建 TOD 本体，[[LOM]] 融合结构化数据库和非结构化文本构建双层企业本体。这大幅降低了本体工程成本，但需权衡自动构建的质量与专家本体的精确性。参见 [[DynamicOntologyConstruction]]。

### 2. 固定vs开放本体的张力与最优解
从严格依赖固定本体（[[Ontology-Enhanced Slot Filling]]）到完全无本体（[[Beyond Ontology DST]]），谱系上的最优解可能是"描述驱动"——[[D3ST]] 用自然语言描述替代符号化本体，保留约束但增强泛化。[[KG Policy Compliance]] 发现 LLM 自发现的 schema 可匹配形式化本体，进一步挑战了"必须预定义本体"的假设。参见 [[DialogueStateTrackingOntology]]。

### 3. 神经符号分离是推理可靠性关键
所有高性能本体推理系统都采用了"LLM规划+符号执行"的分离架构：[[TITAN]] 的路径规划器+图执行器，[[HEAR]] 的证据驱动推理循环，[[KML]] 的神经知识模块组合，[[Husky]] 的动作生成+专家模型执行。LLM 负责灵活理解"要查什么"，符号引擎负责确定性执行"怎么查"——这种分离确保了灵活性和可验证性。参见 [[NeuroSymbolicKGModule]]。

### 4. 正摩擦悖论：减速反而提升任务成功率
[[Better Slow than Sorry]] 的正摩擦本体证明：策略性减速（提问澄清、揭示假设、暂停等待）不仅促进负责任的决策，还提升了任务成功率和机器对用户信念的理解。这挑战了"无摩擦=更好"的传统直觉，与已有wiki的意图澄清策略（[[ConformalIntentClarification]]、[[BayesianDisambiguation]]）从对话节奏角度形成互补。参见 [[PositiveFrictionOntology]]。
