## 一、智能体自进化：技术谱系与前沿进展

"自进化"（self-evolution）指 Agent 通过自身运行经验持续改进能力、知识、策略的过程，无需外部人工干预。近两年研究沿着四条技术路线快速发展：

### 路线 1：记忆进化 — 从存储到经验抽象

| 论文 | 核心机制 | 进化方式 | 启发维度 |
|------|---------|---------|---------|
| [[evo-memory]] (NeurIPS 2025, 71 cites) | ExpRAG 经验检索 + ReMem 精炼管线 | 流式自进化评测：每轮交互后搜索→适应→进化记忆 | 评测方法论 |
| [[agent-memory-survey]] (2026) | Storage→Reflection→Experience 三阶段 | 主动探索 + 跨轨迹抽象 | 演进框架 |
| [[mempi]] (2026) | 按需生成 vs 检索，决策-内容解耦 RL | 独立模型按需生成而非检索静态条目 | 生成式进化 |
| [[peam]] (2026) | MoE-LoRA 参数驻留技能 + 对比内化纠正 | 经验内化到模型参数（参数化进化） | 参数化进化 |
| [[memp]] (ACL 2026) | 程序性记忆 Build/Retrieval/Update | "如何做"技能知识的细粒度→脚本双重蒸馏 | 程序性进化 |
| [[amem]] (NeurIPS 2025) | Zettelkasten 动态索引 + 链接 + 演化 | 记忆条目间自动链接形成知识网络 | 网络化进化 |

**进化层级图谱**：

```
检索式进化（ExpRAG, A-MEM）→ 参数化进化（PEAM, Memp）→ 生成式进化（Mem-π）
       "从库中找"              "内化到权重"            "按需创造"
```

## 二、电信领域映射：从自进化到智能运维/ADN

### 核心映射框架

```
智能体自进化                         电信领域对应
─────────────                      ──────────────
记忆进化 → 经验抽象               →  故障知识库自更新（告警→根因→修复策略）
遗忘/过期机制                     →  告警降噪 + 陈旧配置清理
程序性记忆（"如何做"）            →  修复 SOP 自动提取 + 跨域迁移
参数化进化（经验内化）             →  网络策略参数自动调优（RL fine-tune）
按需生成式进化                    →  应急预案按需生成（而非查历史库）
经验反思与自修正                  →  故障复盘→教训提取→策略迭代
群体协作进化                      →  多域 Agent 协同排障（无线/传输/核心网）
意图驱动自主决策                  →  3GPP Intent Driven MnS → ADN 自治闭环
何时放弃干预                      →  ADN 降级策略（自愈失败→通知人工）
```

### 六大启发深度分析

#### 启发 1：运维 Agent 记忆架构应遵循 Storage→Reflection→Experience 进化

电信运维 Agent 当前多为"告警→规则→动作"的被动存储范式（Storage）。[[agent-memory-survey]]的三阶段框架直接映射到 ADN 三级自治：

| 记忆阶段 | 电信映射 | ADN 自治级别 | 典型场景 |
|---------|---------|-------------|---------|
| Storage（轨迹保存） | 告警日志/配置快照存储 | L1 自监视 | 告警收集、指标采集 |
| Reflection（轨迹精炼） | 根因分析→故障模式提取 | L2 自分析 | 根因定位、影响范围推断 |
| Experience（轨迹抽象） | 修复策略抽象→跨场景迁移 | L3 自决策/自执行 | 策略自动生成、跨域迁移执行 |

**落地建议**：运维 Agent 架构应设计 STM（短时记忆=当前告警流）、MTM（中期记忆=近期故障模式）、LTM（长期记忆=历史修复经验库），并支持三种进化机制：
- 跨轨迹抽象：从多次相似故障中提炼通用修复策略
- 主动探索：Agent 主动查询相关指标/日志以验证假设（而非被动等告警）
- 选择性遗忘：过时配置/陈旧模式自动过期（[[scrapmem]]的光学遗忘机制启发）

#### 启发 2：遗忘/过期是运维 Agent 必备能力，而非缺陷

[[stale]]和[[scrapmem]]首次系统研究遗忘机制——93%存储节省、隐式冲突检测。电信运维面临"告警风暴"和"知识膨胀"问题：

- **告警降噪**：当前系统依赖人工阈值调整。自进化 Agent 应自动识别过时告警模式并过期（[[stale]]的隐式冲突检测直接适用）
- **配置陈旧清理**：网络配置中大量遗留/冗余规则。Agent 应自动检测矛盾配置并触发清理
- **知识库瘦身**：运维知识库随时间膨胀，检索精度下降。遗忘机制保证知识库"活而精"

**落地建议**：运维 Agent 应实现三层遗忘：
1. 硬遗忘（删除）：过时告警模式/废弃配置
2. 软遗忘（降权）：历史经验降权但不删除，长时不可用则自动过期
3. 压缩遗忘（摘要）：长轨迹压缩为结构化摘要，保留关键决策点

#### 启发 3：程序性记忆 → 修复 SOP 自动提取与跨域迁移

[[memp]]（ACL 2026）首次研究程序性记忆——"如何做"的技能知识。当前电信运维的 SOP（标准操作规程）是人工编写的静态文档，无法适应新场景。

**映射**：
- 程序性记忆 Build = 从故障修复执行记录中自动提取修复步骤
- 程序性记忆 Retrieval = 面对新故障时检索最相关 SOP
- 程序性记忆 Update = SOP 自动更新（新增步骤/删除过时步骤）
- 跨模型迁移 = 无线域修复经验迁移到传输域（[[memp]]的"强→弱迁移"启发）

**落地建议**：运维 Agent 应维护两层程序性知识：
- 细粒度步骤指令（step-level）：具体操作命令序列
- 脚本抽象（script-level）：通用修复流程框架
  新场景优先匹配脚本级，细粒度步骤按需从库中检索或生成

#### 启发 4：经验内化 → 网络策略参数自动调优

[[peam]]的MoE-LoRA参数驻留技能和[[mempi]]的按需生成 vs 检索，为网络策略自动调优提供两条路径：

- **参数化进化路径**（PEAM 模式）：修复经验内化到模型参数，下次直接推理而非检索历史。对应：网络 QoS 参数/切片配额→Agent 执行修复→RL 更新策略权重→下次直接推理调参
- **生成式进化路径**（Mem-π 模式）：面对未见故障类型时，独立模型按需生成修复方案而非查库。对应：新型故障无历史案例→Agent 基于领域知识生成应急预案→决策-内容解耦 RL 保证方案可行性

**落地建议**：两种路径各有适用场景——
- 高频常见故障：参数化进化（快速响应，低延迟）
- 低频未知故障：生成式进化（灵活创造，高覆盖）
- 关键约束：决策模块与内容模块解耦（[[mempi]]的RL解耦设计），确保生成方案的安全性验证

#### 启发 5：多域协同排障 → 跨框架经验共享 + 冲突审视

[[agentkb]]的跨框架记忆共享和disagreement gate为多域协同排障提供直接参考：

- **跨域经验共享**：无线/传输/核心网域 Agent 共享故障修复经验，实现"一次修复，全域受益"
- **Disagreement Gate**：当多域 Agent 对同一故障给出不同诊断时，触发审视而非直接投票——这避免了"多数人错误"的集体偏差
- **[[coinbench]]的集体意图理解**：从理解单个域的意图→理解全网意图（跨域SLA约束、端到端体验）

**落地建议**：多域协同 Agent 应实现三层协作：
1. 修复经验库共享（Agent KB 模式）
2. 冲突审视机制（disagreement gate → 触发人工确认或高级推理）
3. 全局意图约束（端到端 SLA 优先级高于单域指标优化）

#### 启发 6：意图驱动 → 3GPP Intent 与 ADN 自治闭环的深度融合

[[intent-signal-theory]]的I*/I-hat/P/O框架与3GPP Intent Driven MnS存在深层对偶：

```
IST 框架                              3GPP Intent 框架
────────                              ──────────────
I* (潜在源意图)                       Intent Expectation (业务需求)
I-hat (可观察代理)                    Intent Report (网络可观测状态)
P (编码载体)                          NRM/Policy (网络策略/规则)
O (模型输出)                          MN Action (网络执行动作)
不可逆意图丢失定理                    → Intent 期望与现实不可完全对齐——需要持续协商
```

[[intentrl]]的RL训练主动意图澄清为 ADN 提供新范式：

- **被动 Intent 处理**（当前 3GPP）：接收 Intent→翻译为 Policy→执行→监测
- **主动 Intent 澄清**（IntentRL 启发）：Agent 在执行前主动与意图方确认细节、消解歧义、发现隐藏约束
- **何时放弃干预**（[[proactive-ai-implications]]启发）：ADN 应内置降级策略——自愈失败时主动通知人工，而非反复尝试造成更大影响

**落地建议**：ADN 自治闭环应从"声明式→执行→监控"扩展为"声明式→澄清→执行→监控→复盘→进化"六阶段闭环，其中"澄清"和"复盘"阶段是自进化的关键入口。
